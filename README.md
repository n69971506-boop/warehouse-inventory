# Складской учёт с мобильным сканером

Учебная практика и курсовой проект, Блок 2, вариант 2.

## Сервер Flask и SQLite

Откройте Warehouse.sln в Visual Studio с компонентом «Разработка на Python» или Warehouse.code-workspace в VS Code. Из корня репозитория на Windows:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
.\.venv\Scripts\python.exe server/app.py
```

Откройте http://127.0.0.1:8000. Карточки сводки показывают весь каталог, товары в наличии или позиции ниже минимума. В последней выборке видно, сколько единиц не хватает до минимального остатка. В панели также доступны поиск, приёмка и отгрузка, журнал и заявки на закупку. Документация API находится по адресу http://127.0.0.1:8000/api. База создаётся при первом запуске. Для отдельной демонстрационной базы задайте `WAREHOUSE_DB` перед запуском. Тесты работают с временной БД:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s server -p tests.py -v
```

Для Android Emulator адрес API — http://10.0.2.2:8000. Для телефона в одной доверенной локальной сети запустите сервер с `$env:WAREHOUSE_HOST = '0.0.0.0'` и введите в приложении LAN-адрес компьютера с портом 8000. Возможность подключения зависит от настроек сети и брандмауэра. Сборка рассчитана на учебный стенд в контролируемой сети.

## Android Studio

Откройте папку `android`. Для сборки используются Android Gradle Plugin 9.4.1, Gradle 9.6.0, Android SDK 37 и совместимый JDK Android Studio. Запустите конфигурацию `app` на эмуляторе или телефоне (Android 7.0+). Чтобы подключить камеру, разрешите доступ, когда откроется экран сканирования. Ручной ввод есть на том же экране. Готовая сборка находится в [Warehouse-debug.apk](Warehouse-debug.apk). Для проверки камеры откройте [тестовый штрихкод](test-barcode.png) на другом экране.

## Демонстрация на чистой БД

1. Откройте «Учёт» и нажмите «Сканировать камерой». Разрешите доступ к камере и поместите этикетку с кодом `4601234567893` в рамку. После считывания Android автоматически найдёт «Кабель USB-C». Для ручного ввода введите код и нажмите «Найти товар».
2. Проведите приёмку 10 шт. Проверьте остаток 10 в каталоге и закрытие стартовой заявки по кабелю.
3. Проведите отгрузку 6 шт. В журнале будет остаток 4. В закупках появится открытая заявка на 16 шт. (20 − 4).
4. Попробуйте отгрузить 5 шт. Сервер вернёт конфликт, остаток останется 4.
5. Примите 1 шт. Остаток достигнет минимума 5, заявка закроется.

Начальные пороги задаются при создании базы в серверном модуле. На чистой базе в каталоге девять демонстрационных позиций с разными остатками. Кабель USB-C из сценария изначально имеет остаток 0 шт. Заявка — внутренняя расчётная потребность. Статус закрытия означает достижение минимального остатка.

## Postman

Импортируйте `postman/Складской учёт.postman_collection.json` в Postman. В коллекции `baseUrl` по умолчанию указывает на локальный сервер. Запустите сценарий на чистой базе. Спецификацию `postman/openapi.json` можно открыть в Swagger Editor.

GitHub Actions запускает тесты Flask при push и pull request.
